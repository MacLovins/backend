# P2 — Парсер и данные

> Памятка для бэкендера, который отвечает за сбор публичных данных о компаниях и за поиск новых компаний.
> Подробное ТЗ: [parser/SPEC.md](../../parser/SPEC.md) · общая картина: [ARCHITECTURE.md](../../ARCHITECTURE.md) §3.1, §4.

---

## 1. Твоя зона

Ты превращаешь интернет в аккуратные документы. На вход — компания (название + домен), на выход — список `Document`
(новости, страницы сайта, вакансии, отчёты) с текстом, датой, ссылкой и языком. Плюс поиск новых компаний по ICP.

| Отвечаешь за | Где |
|---|---|
| Адаптеры источников: GDELT, сайт и newsroom, ATS-вакансии, Wikidata (P0); Google News, HIBP, PDF-отчёты, GLEIF, NewsAPI, Adzuna (P1) | `parser/src/leadradar_parser/adapters/` |
| HTTP-слой: лимиты, robots.txt, кэш, ретраи, блок-лист | `http.py` |
| Нормализация: чистый текст, язык, даты, `content_hash` | `normalize.py` |
| Резолв компании: домены, страница карьеры, какой ATS | `resolve.py` |
| Автопоиск компаний по ICP (Wikidata SPARQL) | `discovery.py` |
| Справочники индустрий и стран | `data/industries.yaml`, `data/countries.yaml` |
| CLI `lr-parser` и фикстуры для P3 | `cli.py`, `tests/fixtures/` |
| Пакетный прогон демо-компаний вместе с P1 | H24–H32 |

**Не твоё:** БД (документы сохраняет P1), анализ и LLM (P3). Пакет `parser` — чистая библиотека: без БД, без FastAPI, без LLM.

## 3. Источники: что и в каком порядке

| Пр. | Адаптер | Даёт сигналы про | Главная хитрость |
|---|---|---|---|
| P0 | `website` | стратегия, программы затрат, трансформация, новости компании | sitemap → выбрать страницы newsroom / стратегии / IR / «о компании» → trafilatura; ≤ 25 страниц |
| P0 | `gdelt` | новости: руководство, инциденты, программы, партнёры | **1 запрос в 5 с на весь процесс**, иначе блок на ~15 мин; окно — максимум 3 месяца |
| P0 | `jobs_ats` | найм (RPA, AI, SOC…) и tech stack из описаний вакансий | найти ATS на странице карьеры; Workday умеет искать по ключевым словам |
| P0 | `careers_html` | найм, когда ATS не найден | только заголовки вакансий, `headline_only` |
| P0 | `wikidata` | фирмографика: страна, индустрия, сотрудники, LEI, Crunchbase ID | один запрос за раз, тайм-аут 60 с |
| P1 | `google_news` | свежие новости | декодирование ссылок хрупкое → если не вышло, берём только заголовок |
| P1 | `hibp` | утечки данных (для Cybersecurity) | каталог скачивается раз в сутки, сверка по домену, атрибуция CC BY 4.0 |
| P1 | `reports` | годовые и стратегические отчёты (PDF) | только страницы с ключевыми словами ± 1 |
| P1 | `gleif`, `newsapi`, `adzuna`, `rss` | юрлицо; новости и вакансии по ключам; RSS newsroom | NewsAPI — только для разработки, на демо-стенде выключен |

**Запрещено:** LinkedIn (любые запросы), Indeed, Glassdoor, обход логина, пейволла и капчи. Блок-лист проверяется тестом.

## 5. Качество данных — твой вклад в точность (25% оценки)

AI находит сигналы только в том, что ты принёс. Мусор на входе = ложные сигналы на выходе.

- **Чистый текст:** trafilatura, без меню, футеров и cookie-баннеров. Страницы < 300 символов отбрасываются.
- **Дата у каждого документа.** Без даты сигнал считается слабее (`undated`). Источники дат: `seendate` у GDELT,
  дата публикации вакансии, `lastmod` в sitemap, дата из HTML.
- **Правильная компания:** в запросах новостей используй юридическое название или алиас, а не только короткое имя
  («DHL Group», а не «DHL»; «Orange SA», а не «Orange»).
- **Дедуп:** одинаковые `canonical_url` и `content_hash` внутри одного сбора — один документ.
- **Метка `headline_only`,** если удалось взять только заголовок: AI снизит его вес.
- **Сбой источника — не авария.** Ошибка одного адаптера → `SourceError`, остальные документы возвращаются.

## 6. Автопоиск по ICP

`discover(countries, industries, employees_min)` → SPARQL к Wikidata ([parser/SPEC.md](../../parser/SPEC.md) §1.7.6) →
кандидаты с доменом из «official website». В `industries.yaml` на H12–H14 заполнить QID Wikidata для каждой индустрии
(1–3 QID, искать на wikidata.org). Id индустрий из списка в SPEC §1.7.7 менять нельзя: на них ссылаются пресеты P3.

## 8. Готово, когда

- [ ] `uv run --package leadradar-parser pytest` зелёный **без интернета**: у каждого адаптера есть фикстура (respx).
- [ ] `lr-parser collect --name "DHL Group" --domain dhl.com --sources news,website,jobs --since 90d --out dhl.jsonl` за ≤ 90 с
      даёт ≥ 10 новостей, ≥ 10 страниц и вакансии (если ATS найден). То же для Lufthansa Group.
- [ ] `lr-parser discover --countries DE,AT --industries logistics,airlines --min-employees 5000` → ≥ 10 кандидатов с доменами.
- [ ] Искусственный 429 или timeout одного источника не роняет `collect`.
- [ ] Запрос к linkedin.com отклоняется ещё до сети (тест).
- [ ] Повторный `collect` в пределах TTL кэша не ходит в сеть.

## 9. Частые ошибки

- Параллельные запросы в GDELT → бан по IP. Только глобальный лимит 1 запрос / 5 с.
- Живые запросы в тестах → CI падает и тратит лимиты. Только записанные ответы (respx).
- Запись в БД из parser → пакет нельзя вынести в сервис. Возвращай документы, сохраняет P1.
- Нет даты или неверная дата (дата сбора вместо даты публикации) → неверная свежесть сигнала.
- Скрейпинг «чуть-чуть LinkedIn» — нет. Решение по условиям не должно от него зависеть.
